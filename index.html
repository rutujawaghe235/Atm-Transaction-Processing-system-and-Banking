Operating system concepts

Theory behind each module of BankOps, mapped to banking and ATM transactions.

Module 1

CPU Scheduling

The OS chooses which ready process gets the CPU so that waiting, turnaround and response times stay low and the CPU stays busy. A preemptive algorithm can interrupt a running process; a non-preemptive one cannot.

Terms

Arrival time (AT), Burst time (BT), Completion time (CT), Priority, Time quantum, Context switch, Convoy effect, Starvation, Aging.

Formulas

TAT = CT − AT WT = TAT − BT RT = first start − AT Throughput = processes ÷ total time

In the bank

Withdrawals, deposits, transfers and inquiries are processes competing for the server CPU.

Module 2

Process Synchronization

Cooperating processes share data, so access to the critical section must be controlled. Without it a race condition corrupts the data. A semaphore is an integer changed only by wait() and signal(); a mutex allows one process inside at a time.

Bounded buffer

empty = free slots, full = filled slots, mutex = 1. Producer: wait(empty), wait(mutex), insert, signal(mutex), signal(full). Consumer: wait(full), wait(mutex), remove, signal(mutex), signal(empty).

In the bank

ATMs produce requests, the core server consumes them in FIFO order. A full queue blocks the producer, an empty queue blocks the consumer.

Module 3

Deadlock and Banker's Algorithm

Deadlock occurs when processes wait forever for resources held by each other. It needs all four: mutual exclusion, hold and wait, no preemption, circular wait. Ways to handle it: prevention, avoidance, detection and recovery.

Banker's Algorithm (avoidance)

Need = Max − Allocation. A state is safe if some order lets every process finish using Available plus released resources. A request is granted only if the state stays safe.

In the bank

Database connections, transaction services and ATM channels are the resources.

Module 4

Memory Management

In contiguous allocation each process gets one block of memory. First Fit takes the first block that fits, Best Fit the smallest block that fits, Worst Fit the largest. Unused space inside an allocated block is internal fragmentation; free holes too small to use are external fragmentation.

Formulas

Internal fragmentation = block − process Utilization = allocated ÷ total memory

In the bank

Each transaction needs a block while it runs; a failed allocation makes it wait.
